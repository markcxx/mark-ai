# 模型资料与评测

模型列表 API（`/api/models` 和 `/api/public/models`）在每个模型上返回可选的 `metadata`。原始 `provider` 和 `id` 保持不变；客户端不得将展示名称用作调用 ID。

## 数据来源

- `lib/model-metadata.ts` 保存已核验的基础规格与显式别名。
- `data/model-catalog.json` 保存公开资料快照，包含 models.dev 的规格和 Artificial Analysis 的评测、参考价格及性能指标，不包含凭据。
- `data/model-overrides.json` 保存部署者的按提供商覆盖，以 `provider/modelId` 为键，值为 `Partial<ModelMetadata>`。例如 `{"my-provider/my-model":{"contextWindowTokens":128000}}`。覆盖未知字段前应核对对应线路说明。价格对象应完整指定币种、输入价、输出价和来源；缓存命中与写入价可选。
- AA API Key 仅通过服务端 `ARTIFICIAL_ANALYSIS_API_KEY` 读取，不返回客户端。部署到服务器时也需要配置此变量才能持续更新 AA 数据；仓库中的公开快照在未配置 Key 时仍可使用。

基础规格优先保留本地核验数据，外部资料补齐缺失字段；提供商精确匹配时可采用其上下文和输出限制。价格优先采用精确匹配提供商的 models.dev 报价，否则采用 AA 模型参考价。自定义转发平台的实际收费由平台决定，界面明确标注参考价。

输入、输出、缓存命中与缓存写入价格均按百万 tokens 展示。只展示实际返回的有限非负数，0 是有效价格；缺失缓存价格显示暂无报价。当前仅展示基础价格，不计算长上下文阶梯、批处理折扣、不同缓存 TTL 和其他服务商附加费。

## 更新与故障回退

运行 `npm run models:sync` 从 `.env.local` / `.env` 加载配置，拉取全部 AA 分页和模型规格，更新公开快照。此命令不调用聊天模型、不产生推理请求。

应用启动优先读取 `.data/model-catalog.json` 的新缓存，否则使用随代码发布的快照。模型列表请求始终先返回已有数据，过期 24 小时后触发后台刷新，同一进程合并并发刷新；故障保留对应来源的完整旧数据与更新时间。运行缓存使用临时文件加原子重命名写入，文件系统只读时仍可使用内存缓存。多实例各自缓存与刷新，不共享请求配额；大规模部署应改为统一同步任务。

重新生成公开快照后需要重新构建部署。运行时缓存更新后，重新加载模型列表即可获得新资料。数据源分页期间若智能指数版本变化，则丢弃本次不完整 AA 更新。

## 评测与雷达图

雷达优先展示智能、编码、Agentic、输出速度和经济性。AA 返回的工程、战略运营、财务会计、经济学、法律和医疗六项专业能力也完整保存。雷达值使用本次完整 AA 快照中对应有效指标的百分位，同值使用并列中点排名。经济性使用 `(3 × 输入单价 + 输出单价) / 4` 的反向百分位。越高越好；这不是 AA 原始分数，也不是固定能力绝对值。快照变化时百分位可能变化。

没有数据的维度不填 0，至少三个有效维度才显示雷达。优先五项不足时，依次以工程、战略运营、财务会计、经济学、法律和医疗中的有效数据补足，最多五维；按固定顺序选取，不按模型最高分挑选。实际轴名称随数据变化，比较时需看轴名。原始指标展开区保留全部有效评分。列表中的蓝条表示智能、绿条表示速度，悬停可查看百分位说明。详情保留原始指数、tokens/s、首字延迟、智能指数版本、来源链接、抓取日期，以及完整 AA 评测名称。Max、High、非推理等配置不可混为当前使用线路的实测结果。没有对应精确 slug/名称的型号不做模糊评测匹配。

规格与评测来源分别记录更新时间。AA 价格与速度可能为跨提供商统计，不能视作当前转发线路的性能或账单。

Web 模型选择器、详情卡、设置列表与上下文指示器使用解析后的资料；服务端上下文裁剪采用同一解析结果。Android 的模型选择器优先使用 API 返回的资料，旧服务端仍回退本地静态规格。Android 原生雷达与价格详情不在此次 Web 界面改动中。
